# 節點 1、2：除去廢 code

對應使用者分類「除去廢code」。這兩個節點的目標是清場，讓後面的結構重組（節點 3～9）在乾淨的基礎上進行。

## 節點 1：移除沒用的檔案

典型目標：舊 CMS（Joomla、WordPress 等）留下的 `html/` 樣板覆寫資料夾、Dreamweaver 的 `Templates/*.dwt`、後端渲染用的 `*.php`（如果專案已經是純靜態、不再跑 PHP）、`.xml` sitemap 以外的設定殘留。

判斷標準只有一條：**整個資料夾或副檔名，在目前上線的頁面裡完全沒有任何連結、`include`、`require` 指向它**。

做法：

1. 先確認網站現在實際怎麼跑——是純靜態檔案直接放上 Apache/Nginx，還是還有 PHP 在跑。如果不確定，問使用者，不要用「這個資料夾看起來很舊」當刪除依據。
2. 對每個候選資料夾，用 `Grep` 搜尋專案內是否有任何檔案引用到它的路徑（例如搜資料夾名稱字串），確認搜尋範圍涵蓋所有 `.html`、`.php`、`.js` 檔。
3. 確認沒有任何引用後才刪除，並在 commit message 寫清楚刪了什麼類別的東西（案例：`移除 html 資料夾、Templates資料夾、XML、php`）。

## 節點 2：掃出沒引用的 css/js 並刪除（含套件）

這是最容易「掃太準也掃太不準」的節點，兩種方向都要注意：

### 掃太不準：只搜 `<link>`/`<script>` 標籤

單純用 grep 找每個 HTML 裡的 `<link href="...">`、`<script src="...">`，再拿反查有哪些檔案沒被任何 HTML 引用到——這是基本盤，但漏掉三種情況：

- **JS 動態插入的 `<script>`**：某些舊套件（如本專案原本的 `addJs.php`）會在執行期用 JS 組出 `<script>` 標籤插入頁面，靜態 grep 抓不到。
- **CSS 的 `@import`**：`.css`/`.scss` 內部彼此 `@import`，不會出現在 HTML 裡。
- **套件內部彼此引用**：例如 `fancybox` 的 helper 檔案是被 `fancybox` 主檔引用，不是被 HTML 直接引用，反查「HTML 有沒有連到它」會誤判成沒用。

### 掃太準：看到「檔案沒被連結」就直接刪

正確流程要多一步「反查誰用了它」，而不是「看它有沒有被連結」：

1. 對每個候選檔案，先確認它有沒有被其他保留下來的檔案（HTML、CSS、JS）引用——不只搜檔名，也搜它匯出的 class 名稱、函式名稱、全域變數名稱是否被別處呼叫。
2. 確認完全沒有引用後，**先移到 `_deprecated/` 之類的暫存資料夾，不要直接刪**，跑過一輪主要頁面（首頁、列表頁、內頁、搜尋頁、404）確認沒有 console error、沒有樣式跑掉，再正式刪除。
3. 套件（`vendor/` 底下整包的第三方庫，如本案例的 `fullcalendar`、`easypiechart`）要當一個單位判斷，不要只刪其中沒被連結的幾支檔案——半殘的套件比完全沒用的套件更危險，之後有人會去 `vendor/` 裡找還在的檔案以為套件還能用。
4. 圖片、字型等資源檔如果只被剛刪掉的 CSS/JS 引用，屬於連帶死碼，一併清掉，但要走同樣的「先觀察再刪」流程，因為圖片常常被 CSS 的 `background-image` 引用，純文字搜尋比較容易漏。

案例：commit message 寫成 `掃出沒引用的css、js 並刪除(套件)`，那一次清掉了 `easypiechart`、`fancy-box` 的 helper 檔、`fullcalendar` 整包、多個版本並存的 jQuery（`jquery-1.10.1.min.js` 與 `jquery-3.1.1.min.js` 同時存在，只有一個真的被引用）。

### 特殊情境：SCSS 遷移後判斷舊版獨立 .css 是否已死

如果專案曾經把手寫的 `.css` 轉成 `.scss` partial（例如 `css/custom.css` 改寫成 `scss/theme/_custom.scss`），舊的獨立 `.css` 檔案通常還留在 `css/` 資料夾裡。這跟前面講的「沒被引用的第三方套件」不同，它是**自己專案的原始檔殘留**，判定死碼時多兩個比反查引用更快的證據來源：

1. **比對編譯入口（`main.scss`）的 `@use` 清單跟 `css/` 資料夾的檔名**：`@use 'theme/custom'` 對應到 `css/custom.css`，同名就代表這支 partial 已經取代了同名的獨立檔案，是候選死碼名單的起點。
2. **檢查 `package.json` 的建置腳本**（`build:css`／`watch:css` 之類）：確認 sass 編譯指令的輸入只有 `main.scss`、輸出只有一支合併後的 CSS，就能直接證明其他獨立 `.css` 檔案不是任何建置流程的輸入或輸出。

這兩步只是縮小候選範圍、加快判斷，**不能取代反查引用**：找到候選之後仍要照上面「掃太準」的流程，搜尋全站 HTML/PHP/JS 確認真的沒有頁面直接 `<link>` 它，再走「先搬 `_deprecated/` 觀察一輪」的既有流程。

### 常見誤區：多版本並存

舊專案常見同一個套件有兩三個版本同時躺在 `js/` 或 `vendor/` 裡（改版時只加新版沒刪舊版）。這種情況下「沒被引用」的判斷要格外小心去重複確認——先確定 HTML 目前引用的是哪一版，再確認其他版本真的無人使用，而不是假設「新版=保留、舊版=刪除」，因為也可能是內頁引用舊版、首頁引用新版這種混用狀態。
